# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a static landing page for **Cloudflash** — a single `index.html` file with no build system, package manager, or dependencies. It announces the platform's relaunch and collects collaboration inquiries via email.

## Deployment

Published on **Vercel** at **cloudflash.com**. No build configuration needed — Vercel auto-detects static sites and serves `index.html` directly. Push to the connected Git branch to deploy.

## Local Development

No build step required. Open `index.html` directly in a browser or serve it with any static file server, e.g.:

```bash
python -m http.server 8080
# or
npx serve .
```

The **Live Server** VS Code extension (by Ritwick Dey) also works — right-click `index.html` → Open with Live Server.

## Architecture

The entire application lives in `index.html` with three embedded sections:

- **`<style>`** — All CSS including keyframe animations (`fadeUp`, `blink`, `pulse`), responsive breakpoints (`@media (max-width: 600px)`), and a blue gradient theme (`#2179c8` → `#1a6bbf`)
- **`<body>`** — Three top-level sections:
  - `.page` — header with animated SVG logo + cursor, hero text
  - `.mesh-zone` — full-viewport-width canvas animation (40 nodes, 120px connection distance) with `.lower` overlay containing the info row (status/timeline/platforms/contact)
  - `footer` — copyright and contact email
- **`<script>`** — Two scripts: email decode + canvas mesh animation. Canvas is sized via `window.innerWidth` × `meshZone.offsetHeight` and reinitializes nodes on resize.

Typography is loaded from Google Fonts (Inter).

## Analytics

Vercel Web Analytics is enabled via a single script tag in `<head>`:

```html
<script defer src="/_vercel/insights/script.js"></script>
```

This script is served by Vercel's edge network and only active in production — it does nothing when running locally.

## Email Obfuscation

The contact email (`hello@cloudflash.com`) is **never written as plain text** in the HTML source. It is base64-encoded and injected at runtime via JavaScript to prevent scraper harvesting:

```js
const e = atob('aGVsbG9AY2xvdWRmbGFzaC5jb20=');
document.getElementById('contact-link').href = 'mailto:' + e;
document.getElementById('footer-email').textContent = e;
```

Do not add the email address as plain text anywhere in the HTML.

## Worker: Email Subscribe / Unsubscribe Flow

The subscribe and unsubscribe flow runs entirely through the Cloudflare Worker at `api.cloudflash.com`, but all subscriber-facing URLs use `cloudflash.com` so the API subdomain is never exposed in emails.

### How it works

- **Subscribe** — Form on `cloudflash.com/fintech` POSTs to `api.cloudflash.com/subscribe`. Worker validates the email, inserts an unconfirmed row in D1, and sends a confirmation email via Resend.
- **Confirm** — Confirmation email links to `cloudflash.com/confirm?token=...`. Vercel proxies this to `api.cloudflash.com/confirm?token=...`. The worker shows a confirmation page (GET), then on submit (POST) marks the subscriber as confirmed in D1 and redirects to `cloudflash.com/fintech?status=confirmed`.
- **Unsubscribe** — Footer link in every email goes to `cloudflash.com/unsubscribe?token=...`. Vercel proxies to `api.cloudflash.com/unsubscribe?token=...`. Worker deletes the subscriber row and redirects to `cloudflash.com/fintech?status=unsubscribed`.

### Vercel rewrites

`app/vercel.json` proxies the two subscriber-facing routes to the worker. The `?:query` suffix is required to forward the token query parameter:

```json
{
  "rewrites": [
    { "source": "/confirm", "destination": "https://api.cloudflash.com/confirm?:query" },
    { "source": "/unsubscribe", "destination": "https://api.cloudflash.com/unsubscribe?:query" }
  ]
}
```

**Important:** `vercel.json` must live in `app/` (not the repo root) because the Vercel project root is set to `app/`.

### Confirm flow: GET before POST

The `/confirm` endpoint intentionally requires two steps — a GET that renders a page, then a POST button click to actually confirm. This prevents email security scanners from auto-confirming subscriptions by pre-fetching links.

## Worker: Known Issues

### Transient JSON parse error on `/test-run` and `/run`

Occasionally the pipeline fails with:

```
SyntaxError: Unexpected non-whitespace character after JSON at position 3
```

This originates in `generateStories()` in `worker/src/index.ts` when parsing either the Anthropic API response or Claude's story JSON output. It is transient — retrying the request immediately resolves it. No code change is needed; just hit the endpoint again.
